# Story 1.1: Project Foundation Setup

## Status
Draft

## Story
**As a** development team,
**I want** to set up the foundational project infrastructure including repositories, CI/CD pipeline, database, and authentication shell,
**so that** we have a solid base to build the motor insurance application upon.

## Acceptance Criteria
1. Backend and frontend repositories are initialized with proper structure and configurations
2. CI/CD pipeline is configured with lint, typecheck, test, build, and deploy stages
3. Database is set up with initial schema and migrations
4. Basic authentication shell is implemented with JWT tokens
5. Environment configuration is properly set up for dev/staging/prod
6. Project runs locally and deploys successfully to development environment

### Technology Stack
[Source: architecture/3-deployment-topology.md, architecture/4-backend-modules-nestjs.md]

**Frontend:**
- Next.js deployed on Vercel (production + previews)
- Edge middleware for i18n/auth cookies
- REST/GraphQL communication with backend
- HTTPS everywhere with HSTS, TLS ≥ 1.2

**Backend:**
- NestJS modular monolith (single deployable with clear module seams)
- Deployment: Fly.io (Singapore primary, Tokyo backup) OR AWS (App Runner/ECS + ALB + WAF)
- JWT authentication with access/refresh tokens
- OpenTelemetry for observability

### Database Schema
[Source: architecture/5-data-model-storage-layout.md]

Core tables to create:
- `users(id, email, phone, verified_at, role, ...)`
- `quotes(id, user_id?, postcode, ncd_percent, ncd_source, sst_rate, sst_amount, pricing_json, status, ...)`
- `drivers(id, quote_id?, policy_id?, full_name, nric_hash, dob, license_class, incidents_json, ...)`
- `vehicles(id, quote_id?, policy_id?, plate, vin?, valuation_value, usage, ownership, safety_json, ...)`
- `policies(id, policy_no, user_id, product, sum_insured_type, premium_total, jpj_submission_status, ...)`
- `policy_drivers`, `policy_vehicles`
- `endorsements(id, policy_id, diff_json, premium_delta, status, ...)`
- `claims(id, policy_id, status, loss_date, police_report_no, od_kfk_flag, workshop_type, ...)`
- `payments(id, policy_id, method, amount, currency, txn_ref, status, ledger_json, ...)`
- `documents(id, policy_id, type, storage_key, hash, issued_at)`
- `audit_logs(id, actor_id, action, entity, entity_id, ts, metadata_json)`

Required indexes:
- `idx_quotes_user`, `idx_policies_user`, `idx_drivers_nric_hash`, `idx_vehicles_plate`, `claims(policy_id,status)`

### Authentication Requirements
[Source: architecture/8-security-architecture.md]

- Passwordless authentication via magic link
- JWT with short TTL
- Refresh token rotation
- Strict aud/iss claims validation
- User roles: customer, support, adjuster, admin
- OIDC for operations

### Environment Configuration
[Source: architecture/14-config-feature-flags-secrets.md]

Feature flags to configure:
- `ncd_required` - Whether NCD verification is required
- `jpj_submit_enabled` - JPJ submission toggle
- `ekyc_required_tier` - e-KYC requirement level
- `psp=providerA|providerB` - Payment service provider selection
- `payments_sandbox` - Sandbox mode for payments

Secrets to manage:
- PSP keys
- JPJ certificates
- NCD keys
- Email/SMS keys
- Tokenization key

Configuration values:
- SST rate (8% for Malaysia)
- Rating factors
- Add-on prices

### Security Considerations
[Source: architecture/8-security-architecture.md]

- PII encryption at rest (DB/objects) + in transit
- NRIC stored as salted hash
- Rate limiting via Redis (token bucket) for hot endpoints
- Audit logs for login, rate, bind, JPJ submit, claims (immutable)
- Row Level Security (RLS): Customer reads gated by `user_id = current_user_id()`

### CI/CD Pipeline
[Source: architecture/3-deployment-topology.md]

GitHub Actions pipeline stages:
- lint → typecheck → test → build → deploy
- Separate environments: dev → staging → prod
- Separate vendor sandboxes/keys per environment
- Terraform for non-Vercel resources

### Testing Requirements
[Source: architecture/12-testing-strategy.md]

- Unit tests for rating math, NCD/tax math, validators
- Contract tests for FE↔BE (OpenAPI)
- E2E tests for quote→bind→JPJ happy path
- Load testing: sustain p95 < 300ms at 500 RPS with ≥95% cache hit
- Security: SAST/DAST, dependency scanning, OWASP checks

### Technical Constraints
- Node.js version: Latest LTS
- PostgreSQL: Managed service with HA
- Redis for caching and rate limiting
- S3-compatible storage for documents
- HTTPS everywhere with TLS ≥ 1.2

## Testing

### Testing Standards
[Source: architecture/12-testing-strategy.md]

- Test file location: Adjacent to source files with `.spec.ts` or `.test.ts` extension
- Backend: Jest for unit and integration tests
- Frontend: Jest + React Testing Library
- Coverage targets: 80% for critical paths
- All tests must pass before deployment

### Key Test Scenarios
1. Authentication flow: Magic link generation and JWT validation
2. Database connectivity and migrations
3. Environment configuration loading
4. CI/CD pipeline execution
5. Deployment health checks
